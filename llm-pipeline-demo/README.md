# Voice chat: ABR ASR → Gemini → ABR TTS

A spoken-conversation loop. Speech recognition and text-to-speech run locally on
ABR's libraries; the reply is generated by Gemini in the cloud.

    1. LISTEN     microphone                 (sounddevice)
    2. TRANSCRIBE speech → text              (ABR niagara ASR, streaming)
    3. THINK      text → reply               (Gemini, cloud API)
    4. SPEAK      reply → speakers           (ABR nith TTS, streamed)

The transcript is streamed into the ASR while you talk, and Gemini's reply is
streamed back and synthesized one sentence at a time, so audio starts before the
full reply has arrived.

## Files

| File | Purpose |
| --- | --- |
| `llm_demo.py` | Interactive pipeline + all the reusable pieces (audio I/O, streaming ASR, Gemini client, streaming TTS). |

The ABR ASR/TTS libraries are **not part of this repo** — obtain them from ABR and
unpack them here so the layout is:

    niagara-38m-live.en-<arch>/          ABR niagara ASR library + model blobs
    nith-5m-live.en-f1-<arch>/           ABR nith TTS, f1 voice (female, default)
    nith-5m-live.en-m1-<arch>/           ABR nith TTS, m1 voice (male, --tts m1)

Use the build matching your CPU (`linux-arm64` on a Raspberry Pi 5).
`llm_demo.py` expects the `linux-arm64` directory names and the default location is in `~/abr-packages`;
point it at other paths by editing `ASR_LIB` / `TTS_LIBS` at the top of the file.

## Setup

1. **Install [uv](https://docs.astral.sh/uv/getting-started/installation/)** (once, if you don't have it):

       curl -LsSf https://astral.sh/uv/install.sh | sh

   `llm_demo.py` declares its Python dependencies inline (PEP 723); `uv` reads
   them straight from the script and builds an ephemeral environment on first
   run, so there's no separate install step.

2. **Install the audio system packages**: 

       sudo apt update
       sudo apt install -y libportaudio2

   `libportaudio2` backs `sounddevice`. Playback goes through `aplay` over
   ALSA by default (`alsa-utils` provides it); make sure the output device is
   set correctly with `raspi-config` or `alsamixer` (HDMI vs. the 3.5 mm jack
   vs. a USB/Bluetooth audio device)

3. **Activate the ABR libraries** once (needs a license key + network; ASR/TTS
   run offline afterwards):

       abr-sdk activate niagara-38m-live.en-linux-arm64/libniagara_38m_live.so   --key-file abr_license.key
       abr-sdk activate nith-5m-live.en-f1-linux-arm64/libnith_5m_live.so   --key-file abr_license.key
       abr-sdk activate nith-5m-live.en-m1-linux-arm64/libnith_5m_live.so   --key-file abr_license.key  # only if using --tts m1

4. Update `ASR_LIB` / `TTS_LIBS` in `llm_demo.py` to the arm64 directory names.

5. **Gemini API key** — get one from Google AI Studio (free):

   1. Go to <https://aistudio.google.com/apikey> and sign in with a Google account.
   2. Click **Create API key** (you can put it in a new or existing Google Cloud
      project), then copy the key.
   3. Put it in the environment, or add it to `llm_demo.py` before running:

          export GEMINI_API_KEY=...      # or GOOGLE_API_KEY

      Add that line to your `~/.bashrc` to persist it across sessions.

   The free tier is enough to try this out but is rate-limited (e.g. a handful of
   requests per minute on `gemini-3.6-flash`); enable billing on the project for
   higher limits. Keep the key secret — don't commit it.

## Run

    ./llm_demo.py                       # start chatting
    ./llm_demo.py --list-devices        # list audio devices
    ./llm_demo.py --input-device 7      # pick a microphone
    ./llm_demo.py --output-device 3     # pick a plughw speaker
    ./llm_demo.py --model gemini-3.6-flash-lite
    ./llm_demo.py --tts m1              # male voice (default: f1, female)

(or `uv run llm_demo.py ...` if the file isn't executable on your system)

Press Enter to start recording, speak, Enter again to stop; `q` then Enter quits.
